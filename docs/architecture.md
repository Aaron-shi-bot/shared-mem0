# 设计说明

Shared Mem0 2026.10.21.2 面向个人开发者，让多个本机智能体共享项目记忆，并通过显式快照接续另一台电脑上的工作。它在官方 Mem0 库之上补充了项目与任务边界、记忆生命周期、长记录检索、备份与设备来源管理。

## 数据所有权与进程边界

每台电脑运行一个绑定 `127.0.0.1` 的 FastAPI 服务。只有该服务进程持有本机 Qdrant 存储，各智能体通过 HTTP、MCP stdio 适配器或 Pi 扩展发起请求。写入在服务端串行保护，避免多个客户端直接争用本地数据库。

每台电脑的程序、配置、私人数据和模型缓存由初始化配置定位。不要把运行中的数据库目录放进多设备同时写入的共享盘；跨设备通过快照传递。

| 数据 | 角色 |
| --- | --- |
| 本机 Mem0/Qdrant 记录与历史 | 本机原创记忆及其来源、范围和生命周期 |
| `data/retrieval.sqlite` | 可重建的全文分段检索缓存，不作为原文的唯一副本 |
| `automation/state.sqlite` | 会话发现状态、片段散列、领取租约、摘要和重试状态 |
| 只读来源分区 | 已由使用者选择并确认采用的其他设备记忆 |
| `backups/portable/` | 本地可移植备份 |
| `backups/google-drive/` | 可选云端快照、待办、核验与收据 |

私人数据不属于公开源码。原生记忆兼容镜像只读取受支持客户端的记忆资产，不移动源文件；具体采集范围需要使用者核对。

## 范围与稳定项目 ID

记录按 `global`、`project`、`task` 范围组织。项目 ID 必须跨智能体和电脑复用；任务记忆另带 `task_id`，来源使用 `source` 与 `source_agent` 标注。

目录映射与项目别名可以辅助归类，但两台电脑的目录路径不同，不能依靠本机路径散列自然得到同一项目 ID。应明确映射到同一个稳定 ID，跨设备导入时也可提供 `project_map`。

`memory_handoff` 同时组织项目决定和任务进展，全局偏好单独返回。检索摘录带来源与生命周期；摘录不足时通过 `memory_get` 读取完整原文。任务尚未核实时应保留未知状态。

## 长记录检索

直接把长记录送入短上下文向量模型会使尾部截断。`PassageIndex` 读取实际 tokenizer 上限，按句子和 token 偏移把完整原文切为有重叠的片段，每个片段都核验不超过模型限制。默认模型为 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`，当前实测 token 上限为 128；切分预算通常为 96 token 并留出余量。

缓存保留原记录 ID、原文和片段位置。查询结合语义匹配、BM25 风格关键词匹配与选择性的标识符加权，再考虑明确的决定角色和历史来源。排序选择最佳匹配片段，返回时仍能追溯原记录。

索引可以在原文、模型或切分逻辑变化后重建。完整覆盖原文解决的是模型输入截断，并不保证每个问题都能准确召回；排序与内容质量仍需实际验证。

## 新旧决定与历史

较新的记录不自动等于正确的当前决定。确认需求变化后，先写入完整的新决定，保留仍有效的条件，再通过 `memory_supersede` 显式连接旧记录与替代记录并给出依据。

默认检索排除已被替代的决定；`include_history=true` 可以查看历史。已确认的替代目标在排序中优先，自动会话观察与历史导入标为参考上下文。相同内容在显示时可去重，原始来源仍保留。

GPT 处理旧会话时必须先对照当前决定，避免把历史陈述重新当作现行要求。没有充分证据时保留并存与不确定性，交由使用者确认。

## 可选会话整理队列

采集器适配 Codex、WorkBuddy、Pi 和 Claude Code 的已落盘会话。启用后，文件变化与安静期共同决定何时生成候选片段。原始会话保留在客户端源位置，队列保存状态和摘要；领取时按来源重新读取，经基础脱敏后输出待处理片段。

外部 GPT 任务负责判断、提炼和提交，程序不内置 GPT 调度，也不在 GPT 不可用时改用规则摘要。领取使用租约与内容散列，提交时重新核验来源，防止提交已经变化的片段。失败和过期领取保留重试状态。

每个摘要条目带分类和片段内的证据消息编号。程序拒绝缺失证据或越界编号；需求、偏好、决定若只引用助手消息，会降为未独立复核的助手报告。已经提炼的文本使用 `infer=false` 入库。

脱敏规则与证据编号都不能替代人工或模型判断。它们不能证明摘要正确，也不能保证捕获所有凭据。外部任务必须把会话视为不可信资料，防止历史指令影响当前操作。

## 本地备份与云端核验

本地备份默认每 24 小时生成普通 ZIP，保留 48 个版本，包含已保存记忆和可选原生记忆资产。SQLite 资产使用一致性快照。新 ZIP 不加密，因此备份目录和云端目标必须按私人数据保护。

云端默认关闭。启用时，本机变化先准备快照和清单；实际上传由使用者授权的外部连接器执行。云端保留 `CURRENT`、`PREVIOUS` 与每日历史，上传成功后仍要独立下载相应对象，与本地清单比对 SHA-256，再提交核验收据。未完成的任务保留待处理状态。

本机服务没有内置云凭据或隐式后台上传。上传时效依赖外部任务、电脑、网络和连接器可用，不能承诺实时同步。`pending`、`local_changes_pending`、最后校验时间和记录数应结合查看。

## 多设备采用流程

1. 使用者明确选择来源设备和备份 ZIP，文件先经过格式和路径检查。
2. 预览展示版本、SHA-256、项目映射及新增、变化、删除和未变数量。
3. 使用者确认后，提交预览散列与先前版本散列；内容或已采用版本变化时拒绝沿用过期预览。
4. 原记录 ID 和设备来源保留在只读来源分区中；来源数据不会混成本机原创再次上传。

云端文件的修改时间只能提示可能有新版，不能单独证明内容最新。已独立验证的内容散列可以确认同一内容；云目录元数据变化后需要重新核验。该方案使用显式采用，尚未实现冲突自动解决或无人值守双向合并。

## 可信边界

默认模型向量化在本机运行，`infer=false` 不请求 LLM。可选的 `infer=true` 会调用使用者配置的 OpenAI 兼容接口；自动会话整理也需要把经处理的片段交给外部 GPT 任务。配置前应确认各自的数据流向。

服务面向可信本机用户：本地 bearer token 保护 API，管理页需要使用该凭据。它不提供企业多租户隔离，不能据此直接暴露到公网。详细边界和漏洞报告方式见 [SECURITY.md](../SECURITY.md)。
